# 如何执行测试与交验

CSV每个适用平台复制一份，不把Intel结果覆盖Windows结果。结果只能用：通过、失败、未执行、不适用、已确认延期。后两种须写原因；未执行不是通过。

优先跑FG-006至019、023至025、029至037、038/039、040至045、050/051：这些直接关系计时、误触发、窗口恢复和安装。之后检查界面与文档。

## 测试数据

用独立用户配置/测试数据目录或fixture，先记录测试数据前置，不清空用户正式记录。精确的25→10分钟场景用隔离可控时钟验证600秒；原生至少用1分钟/短耗时等效场景验证完整事件链，二者都提供。不要给生产设置添加隐藏的“1秒番茄”来冒充1分钟原生测试。

原生手动耗时误差可按±1秒记录，隔离时钟的预期秒数应精确；Mini单击要等系统双击阈值+余量，不能因为未立即开始就误判失败。两窗刷新观察容许约1秒短暂显示差异，稳定状态不能长期不同步。这些容差是本次验收执行标准，不是已量化性能成果。

统计证据要包含：旧轮模式/冻结时长、操作前状态、经过时间、结束后日志条数/seconds/completed、两窗显示和UI轮数。UI分钟做了取整，不用分钟截图代替原始秒数判断。

## 实机与包验证

Mac明确硬件芯片/系统版本；Intel机器与Rosetta两种证据分开。Windows注明系统版本、x64架构、WebView2、DPI。虚拟机说明限制，不能当未测试硬件的覆盖承诺。

安装、窗口恢复、非焦点首击、系统双击速度、原生拖动、置顶透明必须在目标原生环境验证；pnpm test/浏览器录屏无法替代。

证据建议命名 `<平台>-<用例ID>-<构建号>.png/mp4/txt`；每个用例引用相对路径。出现失败保存完整步骤与实际结果，修复后填写新commit和重测证据，不覆盖原失败记录。
